# VoiceMuse

VoiceMuse 是一款面向 Android 的实时变声器项目，当前处于早期开发与设备验证阶段。

## 当前版本：v0.4.2（音频路由、稳定性与基础 DSP 接口）

本版本加入 Oboe 输入/输出流兼容性改进、输出设备枚举与选择、蓝牙设备权限申请、引擎诊断统计，以及输出采样率读取。输出设备选择支持系统报告的内置扬声器、有线耳机、USB 耳机、蓝牙 A2DP/SCO 与 BLE 音频设备。

**重要：** 当前源码尚未完成 Android Studio/Gradle 编译，也未在 Redmi K70 Pro 真机验证。当前 Native 音频路径仍是麦克风到输出设备的基础回放测试，不含音高/共振峰变声 DSP。扬声器测试可能产生声学啸叫，请先降低媒体音量并谨慎测试。

- JDK 17

- Kotlin 2.0.21
- Gradle 8.9（建议版本）
- compileSdk 35
- minSdk 26
- CMake 3.22.1
- Oboe 1.9.3

当前仓库尚未提交 Gradle Wrapper 脚本与 wrapper JAR。可用 Android Studio 打开仓库根目录，由 IDE 配置/同步 Gradle；命令行构建前需生成完整 Gradle Wrapper。若本机 Android SDK 尚未安装 CMake 3.22.1，请通过 SDK Manager 安装。

## 输出设备测试说明

1. 连接有线耳机、配对蓝牙耳机，或选择手机扬声器。
2. 在 VoiceMuse 的“输出设备测试”中刷新设备列表并选择目标输出。
3. 授予麦克风权限后启动监听。
4. 点击“读取引擎统计”，检查实际打开的采样率、设备 ID、欠载与溢出计数。
5. 如果请求的输出设备无法打开，Native 层会回退到系统默认输出。统计中的设备 ID 用于核对最终打开的设备。

设备选择只影响 VoiceMuse 自身 Oboe 输出流，不会自动改变其他应用的麦克风输入，也不代表蓝牙低延迟模式已验证。

## 音频与注入边界

- 默认不 Hook system_server，不全局 Hook 所有应用。
- 默认不启用目标应用作用域；由用户明确选择目标应用。
- Java AudioRecord、AAudio、OpenSL ES 及应用专属音频路径需要分别测试，不承诺通用注入兼容性。
- 普通 APK 的输出路由与向第三方应用提供处理后的麦克风输入是两件不同的事。后者必须通过目标应用进程内适配实现。
- 音频权限仅在用户主动启动监听时申请。
- 不用于录制或处理未经授权的他人音频。

## 设备验证目标

首要测试设备为 Redmi K70 Pro / Android 16 / 官方澎湃 OS，配合用户已安装的 KernelSU 与 LSPosed 环境。具体系统版本、内核和注入状态以设备实际读取结果为准。
