# VoiceMuse LSPosed 目标应用适配设计

## 目标与边界

LSPosed 适配层负责把 VoiceMuse DSP 输出接入**用户明确选择且允许测试的目标应用**的录音输入路径。它与 VoiceMuse 主 APK 的扬声器/耳机输出路由完全独立。

禁止默认全局 Hook 所有应用或 system_server。未完成目标进程内验证前，界面必须显示“未验证”，不能显示“已注入”或“Hook 成功”。

## 分层

- 主 APK：音色参数、DSP 引擎、音频会话、权限与日志。
- Native DSP：统一处理接口，输入/输出 PCM 格式明确，实时回调不做磁盘 I/O、网络请求或阻塞锁。
- LSPosed 模块：读取用户启用的目标包名作用域；仅在目标进程加载适配器。
- 应用适配器：每个应用单独实现并声明支持的录音 API、采样率、声道、PCM 格式和版本范围。
- 状态回报：区分模块已安装、作用域已启用、目标进程已加载、录音 API 已命中、替换 PCM 已验证五个状态。

## 适配顺序

1. Java AudioRecord：优先验证初始化、read(ByteBuffer/short[]/float[]) 和录音状态变化；只在目标进程中处理。
2. AAudio：检查应用是否使用 NDK AAudio，并按其流格式转换 PCM。
3. OpenSL ES：仅对仍使用该路径的目标应用适配。
4. 应用专属音频链路：对自定义引擎、游戏语音 SDK 等建立独立适配器。

## PCM 契约

适配器必须读取真实输入参数：采样率、通道数、编码格式、缓冲区长度和时间戳。进入 DSP 前转换为统一浮点 PCM；输出时再按目标 API 的格式转换。必须处理短读、静音帧、停止/释放、线程并发、音频焦点变化和设备切换。

## 验收标准

- 非目标应用不受影响。
- 目标应用退出或停止录音后，不残留后台录音线程。
- 目标应用确实收到处理后的 PCM，而不是仅显示 Hook 日志。
- 录音权限、隐私指示与系统录音状态保持正常。
- 每个应用/版本单独记录成功与失败，不外推为“全应用兼容”。

## 当前状态

本文件是实施规格，不代表 LSPosed 模块或任何应用 Hook 已实现。当前仓库尚无可安装的 LSPosed 适配模块。
